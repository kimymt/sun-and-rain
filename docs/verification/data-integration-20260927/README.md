## データ設計

| 取得元 | API指定 | 項目 |
|---|---|---|
| weather | best_match | temperature_2m、precipitation、sunshine_duration、shortwave_radiation、relative_humidity_2m、wind_speed_10m、is_day、weather_code |
| uvpop | gfs_global | uv_index、precipitation_probability |

両方24時間・unixtime・Asia/Tokyo。気温°C、風速m/s、降水mmをリクエストで固定する。日照は応答の秒を保存し表示時に分へ変換。日射量は正規化して保持するが主画面には追加しない。

取得元ごとに`sourcePolicyId`、地点ID・改訂番号、取得時刻、指定モデル、グリッド座標、指標別系列を保持。モデル初期化時刻は未提供のためnull。系列の要素は`targetTime`、`start`、`end`、`aggregation`、`value`。瞬時値の`end`はnull、区間値はAPI時刻Tに対し`[T-3600,T)`。

表示区間の開始Tに対して、気温等の瞬時値はT、降水・日照・UV等はT+3600のAPI値を参照する。配列位置による結合はしない。正時開始なら12区間、それ以外は両端の一部を含む13区間。端の値を比例配分しない。正時の昼夜区分を背景に使い、日の出・日没の分単位の表現とは区別した。

不正な単位、配列長、重複・欠落時刻、必要な期間を含まない応答は取得元単位で拒否。値単位の欠損・不正値はnull。欠損を0にしない。片方だけ失敗した場合に別モデルへ切り替えない。同じページ内の以前の値があれば元の取得時刻を維持し、失敗を表示する。1時間以上前の取得値には注意表示を付ける。

## 利用量の確認

`review-service-costs`で呼び出し経路を確認した。起動・手動更新1回につき2リクエスト、各15秒でタイムアウト。自動更新は前面で30分ごと、同時更新を抑止。即時の自動再試行なし。

例として1人が短時間の起動を1日10回なら20リクエスト/日。1タブを24時間未満前面に置き続ける場合は起動込み約48回×2=96リクエスト/日。10タブなら約960。手動更新・再読込は別途加算される。ボタン無効化は同一ページ内の多重実行防止であり、複数タブ全体の上限ではない。

[公式料金](https://open-meteo.com/en/pricing)と[利用条件](https://open-meteo.com/en/terms)を当日確認。無料APIは非商用向け。分600・時5000・日10000・月300000の制限が掲載されている。今回の個人利用想定は無料枠内。有料エンドポイント・APIキー・決済契約は導入していない。同じIP等からの他の利用量は未確認。
