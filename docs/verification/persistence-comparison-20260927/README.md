# 端末保存・予報差分

2026-09-27。東京固定の実データ版に、IndexedDB保存と前回表示からの差分を追加。

## 表示と比較元

「表示した」は、前面の文書に12時間のタイムラインを描画し、2回のrequestAnimationFrameを経た状態と定義する。読んだことや理解したことを推定する仕様ではない。詳細カードを全て開く必要はない。

- 取得が完了しただけでは比較元へ昇格しない。非表示中は保存・表示時刻を更新しない。
- 取得応答を採用する時点で、最後に表示したスナップショットを比較元に固定。再描画や時間選択で強調を消さない。
- 前面で時間窓が進んだ場合は、その表示範囲を新しい最終表示として記録する。比較対象は元の24時間全体ではなく、保存した12時間窓と重なる対象時刻のみ。
- 最新の取得が全て失敗した場合は履歴を上書きしない。一部成功の場合は表示した取得元別データ・取得時刻・失敗状態を保存する。
- 再読込時は保存値を先に表示して最新取得を開始する。最初に見せたキャッシュで比較元を上書きしない。
- 同じ地点ID・座標改訂・座標、同じ取得元方針、同じUTC対象時刻を比較。日付の異なる同じ時刻を結合しない。
- 現在進行中・過去、未表示の未来、欠損からの復旧は変化として強調しない。最新取得に失敗した取得元も比較しない。

## 強調ルール

丸め前の値を使う。以下はアプリの表示ルールで、気象の精度や行動を保証する閾値ではない。

| 指標 | 閾値 |
|---|---|
| 降水確率 | 差20ポイント以上かつ一方が40%以上、または40/60%の境界をまたぎ差10ポイント以上 |
| UV・1時間平均 | 差2以上、または3/6/8/11の境界をまたぎ差1以上 |
| 降水量 | 差0.5mm以上、または0.2mm/時の境界をまたぎ差0.2mm以上 |
| 日照 | 差20分/時以上 |
| 気温 | 差2℃以上 |

増減両方向を扱い、同じ指標・方向の連続区間をまとめる。上部は最大3グループ、内訳には全件の前後値を表示する。タイムラインの破線と選択時間の文章でも変更を示す。湿度・風速・天気コードは数値の比較対象に加えない。

降り始めの移動は降水量だけで判定する。新旧双方に共通する未来の完全な時間区間があり、欠損がなく、双方の先頭区間が0.2mm未満で、その後に0.2mm以上の区間が現れた場合だけ開始時間帯を比較する。進行中、片方だけ雨がある場合、共通窓外、欠損を挟む場合は開始移動を出さない。「16時台」の見込みであり、分単位の開始予測とはしない。

## 保存モデル

IndexedDBの`sun-and-rain`、DB版1、`locations`ストア。キーは`location.id`。現在は東京1レコード。各地点に最後と比較元の2スナップショットをまとめて、1トランザクションで保存する。

```text
LocationRecord
  schemaVersion: 1
  location: { id, revision, name, latitude, longitude }
  last: DisplayedForecast
  previous: DisplayedForecast | null

DisplayedForecast
  location: Location
  displayedAt: UTC epoch秒
  windowStart: 表示窓の開始epoch秒
  windowEnd: windowStart + 43200
  sources: { weather, uvpop }
    data: { sourcePolicyId, fetchedAt, modelRunAt, series, ... } | null
    error: string | null
```

各sourceの構造は[実データ接続の記録](../data-integration-20260927/README.md)参照。元の24時間データは再表示のために保存するが、比較対象の範囲は別に記録する。取得時刻・表示時刻・対象時刻を分離する。典型的な2スナップショットのJSONは数十KB程度。履歴を追加し続ける方式ではない。

取得値または表示が48時間より古い場合は、読込時に予報を無効化して地点だけを維持する。期限切れ内容は次回の正常保存で置換する。閉じたブラウザ内での物理削除を保証するタイマーは設けない。

読込時に型・系列・時刻・ソース方針を検証する。破損は使用せず、正常な予報を表示した後に置換。未知の保存形式は上書きせず保存を停止する。保存拒否・容量エラー・タイムアウトは画面内の保持へ切り替え、保存済みと表示しない。

別タブとの書込みはIndexedDBのトランザクション内で既存レコードを読み、古い表示時刻または古い取得値で新しいレコードを上書きしない。タブ間の画面同期は追加していない。

### 途中で修正した点

既存の回帰テストは欠損を画面に表示した直後、保存完了を待たずに再読込していた。保存対応後には、その一つ前の正常値が復元されるため「欠損2件」の期待と一致せず失敗した。保存状態を待ってから再読込する手順に直し、再実行した。全失敗の初回起動テストだけは専用プロファイルのDBを明示的に空にする。保存復元テストはDBを消さずに行う。

保存APIへのアクセス拒否でブラウザ由来の英語メッセージが出たため、日本語の保存不可表示に統一した。取得情報を折りたたみ、変更概要とタイムラインを先に配置した。
